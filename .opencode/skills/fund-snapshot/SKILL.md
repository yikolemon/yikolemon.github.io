# 基金快照

把「一次统计」变成 `_data/fund/snapshots/YYYY-MM-DD.json` 里的一个文件。

页面是 `repo/fund.html`（地址 `/fund/`），**只读数据、自己算派生数字**。
所以这里唯一的工作是：**把两个绝对额抄准，把 id 对齐**。

下面所有路径都相对 `repo/`，命令都在 `repo/` 里跑。

## 铁律

1. **每只基金只写两个数字** —— `invested`（累计投入）和 `value`（当前市值）。
   收益 / 收益率 / 占比 / 变化 / 份额**一律不写**，页面自己算。
2. **只新建，不修改** —— 一次统计 = 一个新文件。**永远不要回头改旧快照**，
   否则「上一次的数字」就变了，页面上整列「变化」跟着一起错。
3. **`id` 是永久主键** —— 写进 `funds.json` 就不要再改。
   拼错**不会报错**，那只基金会从页面上静默消失。
4. **口径固定，别混**：`invested` 是不含费用的累计投入，`value` 是当前市值。
   详情见下面的「口径」。
5. **不猜** —— 数字对不上、只给了合计、名字认不出，都去问，不要自己圆。

## 数据在哪

```
repo/_data/fund/
├── meta.json               标题 / 币种 / is_placeholder
├── funds.json              基金档案，一只一条，只填一次
└── snapshots/
    └── YYYY-MM-DD.json     一个文件 = 一次统计；日期取文件名，文件里不写 date
```

`snapshots/` 里**没出现**的基金 = 当时没持有。下次再出现会被标成「新建仓」，
所以清仓的基金不要留空行，直接删掉那一行。

## 工作模式：截图全自动（推荐）

用户把这一期的截图**全部丢给你**，文件名带 App 名
（`支付宝-2026-10-24-持仓.png` / `广发基金-2026-10-24-持仓.png` / `国信证券-...`）。
你在**一次会话里跑完整条流水线**，最后让用户去本地页面验收就行：

```
收图 → 读图 → 汇总表 → 交叉验算 → 对齐 id / 补 funds.json → 写快照
→ fund.py check → 本地预览 → 交验收
```

- **渠道从文件名判**：支付宝 / 天天基金 → `场外分销`；基金公司自家 App
  （广发基金 / 南方基金 / 天弘基金…）→ `场外直销`；券商（华泰 / 国信 / 中信…）→ `场内`。
  文件名没写 App 或认不出 → **先问，别猜**。
- **先建汇总表，再动手写**：把所有截图读完，拼一张 `基金 × 渠道 × 成本 × 市值` 表，
  逐格验算过，才进下一步。不要读一只写一只。
- 汇总表里任何一格对不上 / 缺数据 → **攒成一页「待确认」一次性问用户**，
  不要中途反复打断。
- 跑完**只交本地验收**，不主动 push，用户说提交再提交。

## 截图怎么读

**每只基金读三件套**：持有金额 / 持仓成本 / 持有收益，必须满足
`持有金额 = 持仓成本 + 持有收益`。对不上就是读错了，重新放大。

- **先放大再读**：用 PIL 把数字列裁出来，放大 3~5 倍再逐位读
  （第一次初始化没放大，`107.71` / `117.71` 就差点看岔）。
- 页面通常给「持有金额 + 持有收益」，成本 = 金额 − 收益；有「持仓成本」就直接读。
- **别用「持有收益率」反推投入** —— 收益率口径各家不一。
- 场内按「成本价 × 持股 = 成本、现价 × 持股 = 市值」。
- **代销以平台 App 为准**（支付宝等），基金公司 App 里的「XX-代销」
  可能滞后，只用来确认直销。

| App | 渠道 | 读数要点 |
| --- | --- | --- |
| 支付宝 / 天天基金 | 场外分销 | 列表页「持有金额 / 持有收益」；成本 = 金额 − 收益 |
| 广发基金 / 南方基金 / 天弘基金… | 场外直销 | 持仓详情「总资产 / 持仓成本 / 累计收益」直接读 |
| 券商（华泰 / 国信 / 中信…） | 场内 | 成本价 × 持股、现价 × 持股 |

- **交易确认中**：份额为 0 的「确认中」申购，App 常显示市值 = 金额。
  默认**不算进本期**（确认后下次再记），拿不准就问 —— 第一次初始化时
  南方 A 直销两笔各 10 元就是这样处理的。
- **现金分红 / 卖出**：会掉市值不掉投入 → 见「口径」，先问用户再定。
- **日期口径**：场外 QDII 净值滞后（10-15/10-16 净值），场内按统计当日收盘，
  同一天混记允许，写进 `note` 即可。

## 口径

页面里的「口径说明」和这里是同一套，**改一边要改另一边**。当前的约定：

- `invested` = **累计投入**，**不扣减**申购费 / 佣金
- `value` = 当前市值（场内按收盘市价，场外按最新确认净值）
- 页面收益 = `市值 − 累计投入`，是**累计收益**；持续定投会稀释收益率，所以以金额为主

### 两个会算出假亏损的坑

页面只会做 `收益 = 市值 − 投入`。任何让「市值掉、投入不掉」的操作都会显示成一笔**虚假亏损**：

| 情况 | 为什么会假亏 | 怎么办 |
| --- | --- | --- |
| **现金分红** | 钱打到余额，市值掉了，投入不变 | 确认是**红利再投资**；若是现金分红，**先问用户**要不要从投入里扣掉 |
| **卖出 / 赎回** | 拿回本金，市值掉了，投入不变 | 同上，**先问用户** `invested` 是否按「净投入」扣减 |

这是**当前还没遇到过**的情况（现在只有定投、没有卖出）。碰到了**先停下来问用户**，
不要自己决定口径 —— 定了就要写进页面的「口径说明」，否则时间序列前后不可比。

## funds.json 字段

| 字段 | 必填 | 取值 / 说明 |
| --- | --- | --- |
| `id` | ✓ | 永久主键。小写 ASCII，`公司拼音_标的`，如 `tianhong_nasdaq100`、`morgan_sp500`。只用小写字母 / 数字 / 下划线，全局唯一 |
| `name` | ✓ | 全称，尽量和 App 里显示的一致 |
| `code` | | 基金代码。**场内的 6 位代码一定要填**（如 `513100`）；场外没有就写空串 `""` |
| `venue` | ✓ | 只有 `场内` / `场外` |
| `channel` | ✓ | 只有 `场内` / `场外直销` / `场外分销` —— **页面「按渠道」维度用的就是它** |
| `platform` | | 自由文本：`券商·华泰` / `支付宝` / `天天基金` / `富国基金官网` |
| `tracking` | | 跟踪标的：`纳斯达克100` / `标普500` / `沪深300`；主动基金写策略 |
| `category` | | `ETF` / `QDII指数` / `指数基金` / `主动基金` / `债券` |

### venue / channel 怎么判

| 在哪买卖 | `venue` | `channel` |
| --- | --- | --- |
| 券商 App（华泰 / 中信…） | `场内` | `场内` |
| 基金公司官网 / 自家 App | `场外` | `场外直销` |
| 支付宝 / 天天基金 / 蛋卷等第三方 | `场外` | `场外分销` |

`channel` 是最常漏的字段（`fund-data-real-backup-2026-10-17.json` 里十只全缺），
漏了页面会把这些基金归到「未分类」，`fund.py check` 会提醒。

## 快照文件长什么样

```json
{
  "note": "首次统计 · 仅支付宝场外",
  "holdings": [
    { "id": "tianhong_nasdaq100", "invested": 5200.00, "value": 5605.58 }
  ]
}
```

- `note` 可空，写一句当天的情况（「补上券商账户」「卖出 300ETF 一半」）
- `holdings` **只列当时有持仓的基金**
- **不要写 `date`** —— 日期取文件名，写了 `check` 会提醒删掉
- 金额用数字，不要用字符串；保留两位小数

## 流程（一次会话跑完，不中途打断用户）

1. **收图** —— 找桌面（本机 `E:\快速访问\桌面`）或用户指定的目录，按时间排；
   从文件名判 App → 渠道，建一张「截图清单」。
2. **读图** —— 逐张放大读数，填汇总表（基金 × 渠道 × 成本 × 市值）。
3. **验算** —— 每只 `金额 = 成本 + 收益`；同渠道合计 vs App 页脚合计。
   对不上 → 攒「待确认」一次性问用户。
4. **对齐 id** —— 每只都要能在 `funds.json` 里找到；
   新基金先补档案（venue / channel / tracking / category 全填），再写快照。
   不要编新 id，页面只认 `funds.json` 里已有的。
5. **写快照** —— `python script/fund.py new <日期>` 用上期做模板，只改
   `invested` / `value`，删掉本次没持有的行；同一天只能一份。
6. **校验** —— `python script/fund.py check`，报错先修再往下。
7. **本地预览** —— `bundle exec jekyll build`，确保 4000 server 活着，
   确认 `/fund/` 数字和汇总表一致。
8. **交验收** —— 把汇总表 + 变更摘要发给用户核对；**不主动 push**，
   用户说提交再提交（`git add _data && git commit && git push`）。

## 对账

写完自己加一遍，和 App 里的合计对照：

- 累计投入 ↔ App「累计买入」/「总成本」
- 总市值 ↔ App「总资产」/「持仓市值」
- 收益 = 市值 − 投入

```bash
cd repo && python -c "import json,io;d=json.load(io.open('_data/fund/snapshots/2026-10-17.json',encoding='utf-8'));i=sum(h['invested'] for h in d['holdings']);v=sum(h['value'] for h in d['holdings']);print('投入 %.2f  市值 %.2f  收益 %+.2f (%+.2f%%)'%(i,v,v-i,100*(v-i)/i))"
```

对不上就先别提交，把差异定位到具体哪只基金。

## 输入形态

| 形态 | 怎么做 |
| --- | --- |
| **一批截图（推荐）** | 文件名带 App 名，全部走「截图全自动」流水线 |
| **复制粘贴的文字** | 直接解析；注意别把「持有收益」当「累计投入」 |
| **手打清单** | 先 `fund.py new <日期>` 出模板再填，省得对不齐 |
| **只给合计** | 停下来要单只明细，拆不开等于编数据 |

## 常见错误（都是「不报错但数据错」）

| 症状 | 后果 | 谁会发现 |
| --- | --- | --- |
| `id` 拼错 | 那只基金静默消失，总数凭空变小 | `check` + 页面顶部橙条 |
| 漏抄一只 | 少算一只 | `check` 提醒「上次有、这次没写」 |
| `invested` 倒退 | 没清仓却倒退 | `check` 提醒「抄错了吧」 |
| 同一天两份文件 | 文件名唯一，不可能 | 新建时就会拒绝 |
| 把「持有收益」当投入 | 收益变负数 | 一眼能看出来 |
| 分红 / 卖出没扣 | 虚假亏损 | 见「口径」 |

## 工具

```bash
cd repo
python script/fund.py check            # 查 id 拼错 / 漏记 / 投入倒退 / 日期乱序 / JSON 语法
python script/fund.py new 2026-10-24   # 用上次持仓做模板新建快照（不覆盖已有文件）
```

`check` 专门抓那些「不报错但数据不对」的问题 —— 尤其是 id 拼错。
页面自身也兜底：快照里出现 `funds.json` 没有的 `id` 时，顶部橙色提示条会把它们列出来。

## 背景

- 页面 `repo/fund.html` → `/fund/`，数据用 `{{ site.data.fund | jsonify }}` **构建时注入**，不走 fetch
- 图表库自托管在 `repo/assets/js/`（Chart.js / Hammer / zoom 插件），**不要改回 CDN**
- 本目录在 `repo/.opencode/` 下，Jekyll 默认忽略点开头的目录，所以**不会**发布到站点
- 用户习惯把这一期的截图放桌面（本机 `E:\快速访问\桌面`），文件名带 App 名
